GastroClinic27 — Interview Preparation

Evidence-based from the workspace code. “Implemented”, “partial”, and “future” claims are intentionally separated.

60-second project introduction: GastroClinic27 is a responsive React single-page website for a gastro clinic network. It shows clinic schedules, services, contact paths, testimonials, and appointment/enquiry forms. It uses Vite, React, React Router, Tailwind CSS, Framer Motion, Lucide icons, Web3Forms, and an OpenRouter chat widget. It has no custom backend, database, authentication, live booking, admin dashboard, or secure server-side AI proxy in this repository.

2. Project architecture

index.html → src/main.jsx → App.jsx → BrowserRouter → TitleUpdater + ScrollToTop + shared shell → Navbar | AnimatedRoutes/pages | Footer | WhatsAppButton | DrVayuGuide → local state/static data/external APIs

Folder structure

  • src/pages: route screens
  • src/components: shared UI
  • src/data/index.js: content/data
  • src/hooks: useDarkMode
  • src/lib/config.js: Web3Forms config
  • public/images: assets

Config files

  • package.json: scripts/deps
  • tailwind.config.js: theme/dark mode
  • vite.config.js: React plugin
  • public/_redirects: SPA fallback
  • index.html: metadata/fonts/root

MEDIUMExplain the architecture.

Pages are separated from reusable components. main.jsx boots React. App.jsx owns routing, shared layout, titles, scroll handling, and page transitions. Pages import central data or own local state. Context, Redux, a custom backend, and global store are not used.

Follow-up: Shared components are Navbar, Footer, WhatsAppButton, DrVayuGuide; pages describe whole route screens.

What happens on /clinics?

Router selects ClinicsPage without full reload. TitleUpdater sets title, ScrollToTop resets position, AnimatedRoutes performs transition, and ClinicsPage maps over the clinic data array.

Explain data flow.

Static display data is imported from data/index.js. Controlled inputs write local state; page validation checks it; JSON is posted to Web3Forms. Chat state is local and sends to OpenRouter. API responses update local success/error/message state.

3. React interview

EASYHow are components used?

Function components divide the UI: Navbar manages navigation, AppointmentPage owns request logic, DrVayuGuide owns chat, Footer displays shared information. They return JSX that React renders.

Props vs state: examples.

Props are inputs such as StatCard({ icon, value, label, color }) in HomePage. State changes within a component: Navbar isOpen, AppointmentPage form, DrVayuGuide messages.

Props flow down; state setters trigger re-render.

Where are useState/useEffect/useRef used?

useState: menus, theme, forms, sliders, FAQ, loading/errors/chat. useEffect: title, scroll, listeners, timers, system theme, focus/scroll chat. useRef: counters and chat input/end DOM nodes.

HARDHow do list rendering and keys work?

map renders nav links, clinics, services, testimonials, FAQ, and images. Repeated elements have keys, normally stable paths/names/IDs, used by React reconciliation. Prefer stable IDs over index when order can change.

Theoretical concepts to know

  • Virtual DOM: React reconciles virtual tree changes with the DOM.
  • Controlled input: state owns value and onChange updates it; forms here are controlled.
  • Context API: shared state mechanism; NOT IMPLEMENTED.
  • React.lazy: code splitting; NOT IMPLEMENTED.

4. JavaScript interview

Concepts actually used

  • const/let: fixed bindings and changing counters.
  • Arrow functions: handlers like e => setInput(e.target.value).
  • Destructuring: pathname from useLocation.
  • Spread: {...form,[field]:value} immutable update.
  • map/find/filter: lists, selected clinic, chat history.
  • Modules/template literals: imports/exports and URLs/subjects.

MEDIUMExplain async/await and try/catch.

Form/chat handlers are async. They await fetch and res.json, set success/error state, catch network exceptions, and use finally to clear loading. Chat checks res.ok; form handlers check data.success.

Follow-up: HTTP 400 normally does not automatically go to catch; inspect response status/data.

Closure/event loop example.

Timer callbacks in HomePage retain surrounding variables, which is closure. The event loop lets timer/network callbacks run after synchronous work so UI remains responsive. Effects clean intervals/timeouts/listeners.

5. React Router

How is routing implemented?

IMPLEMENTED BrowserRouter wraps App. Routes contains fixed Route paths for all pages and wildcard 404. Link handles internal navigation.

Link vs anchor?

Link is for internal SPA routes; anchors are for external WhatsApp/Maps/social and tel:/mailto: actions.

Dynamic/nested routes?

NOT IMPLEMENTED No route params/nested Outlet. Clinic selection is query string ?clinic=id, read through useSearchParams in AppointmentPage.

Why _redirects?

IMPLEMENTED The /* /index.html 200 rule enables SPA fallback on compatible static hosts. Actual hosting setup is not in the repo.

How is it responsive?

Mobile-first Tailwind prefixes: Navbar has hidden lg:flex desktop links and lg:hidden mobile controls. Grids use patterns like grid-cols-1 md:grid-cols-2 lg:grid-cols-4. Text and spacing use sm/lg variants.

What is customized?

7. Framer Motion

Why and where?

IMPLEMENTED Motion is used for App route transitions, mobile menu, reveal/card animations, counters/sliders, WhatsApp, and DrVayuGuide.

initial/animate/exit/variants/viewport?

8. Web3Forms

How does it work?

IMPLEMENTED lib/config.js exports VITE_WEB3FORMS_KEY. HomePage, AppointmentPage, ContactPage POST JSON to api.web3forms.com/submit with access_key, subject, and fields; each parses JSON and updates success/error/loading state.

What data is sent?

Home: name/phone/condition/location/message. Appointment: consultation type, patient details, clinic/date/time/symptoms. Contact: name, optional email/phone, message.

Security answer.

PARTIALLY IMPLEMENTED Client validation exists. FUTURE IMPROVEMENT Add server validation, anti-spam, rate limiting, privacy process. Never call a Vite client env value a secret.

9. OpenRouter / AI assistant

How does Dr. Vayu work?

IMPLEMENTED DrVayuGuide reads VITE_OPENROUTER_API_KEY, stores messages in React state, builds SYSTEM_PROMPT + prior conversation, and POSTs to OpenRouter chat completions. Model string: openai/gpt-oss-120b:free; max_tokens: 400.

What happens on send?

  1. Blank/loading/missing-key input is blocked.
  2. User text is appended and loading starts.
  3. Messages map to API roles; fetch sends JSON/headers.
  4. Success appends data.choices[0].message.content.
  5. API/network errors append warning; finally ends loading.

Why not diagnosis?

Prompt restricts scope to clinic/basic awareness and tells medical symptom users to see a doctor. That is only frontend prompt guardrail, not guaranteed model safety; never claim diagnosis/emergency care.

HARDHow is API key protected?

NOT IMPLEMENTED It is not securely protected: VITE_ values are browser-visible and fetch is client-side. FUTURE IMPROVEMENT serverless/backend proxy, rate limits, moderation, output checks, monitoring, provider restrictions.

10. API concepts

Explain API/HTTP/JSON/CORS here.

API is software communication. The app POSTs to Web3Forms/OpenRouter. Requests have URL, method, headers, JSON body; responses use res.json. CORS is browser cross-origin permission controlled by API server. This project consumes APIs; it has no self-built REST routes/controllers/database.

14. Security

Implemented vs recommended

Implemented
  • Basic client validation.
  • React ordinary text rendering; no inspected dangerouslySetInnerHTML.
  • noopener/noreferrer on blank links.
  • AI scope prompt.
Production recommendation
  • Server key protection/validation/rate limit.
  • CAPTCHA, auth/roles/audit logs.
  • Prompt-injection/moderation controls.
  • Formal XSS/CSRF/CORS policy.

XSS, CSRF, CORS, prompt injection?

XSS is injected script/content; React escapes ordinary strings but untrusted data still needs care. CSRF is unwanted authenticated request; no own cookie backend exists now. CORS is cross-origin browser permission. Prompt injection tries to override AI instructions; prompt alone is insufficient.
